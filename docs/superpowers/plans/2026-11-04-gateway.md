# Rust IoT Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a tested Rust PC Gateway that ingests NanoMQ telemetry, keeps latest device state and a durable ThingsBoard outbox, routes CoreIOT RPC and basic dashboard controls to local devices, and serves a small HTMX dashboard.

**Architecture:** One Tokio/Axum Rust process with focused modules. NanoMQ is a separate local broker. SQLite commits latest-state updates with outbound telemetry; a ThingsBoard MQTT Gateway API client sends outbox items and receives RPC. The UI is server-rendered MiniJinja + HTMX + CSS.

**Tech Stack:** Rust stable, Tokio, Axum, rumqttc, SQLx SQLite, Serde/serde_json, MiniJinja, HTMX, plain CSS, NanoMQ.

## File map

- Create `gateway/Cargo.toml`, `gateway/Cargo.lock`, `gateway/src/main.rs`: crate metadata and application startup.
- Create `gateway/src/config.rs`: validated environment configuration, device map, and command allowlist.
- Create `gateway/src/telemetry.rs`: local telemetry contract and normalization into device name, timestamp, and values.
- Create `gateway/src/command.rs`: strict ThingsBoard/local command decoding and device/topic mapping.
- Create `gateway/src/store.rs` and `gateway/migrations/0001_init.sql`: latest state, durable outbound telemetry, retry bookkeeping.
- Create `gateway/src/local_mqtt.rs`: NanoMQ subscriptions, telemetry ingestion, local command publishing, and device acknowledgements.
- Create `gateway/src/thingsboard.rs`: ThingsBoard MQTT session, downstream device connect, telemetry publish, and RPC receive/reply.
- Create `gateway/src/outbox.rs`: queued telemetry delivery and bounded retry scheduling.
- Create `gateway/src/web.rs`, `gateway/templates/index.html`, `gateway/templates/_devices.html`, `gateway/static/style.css`: local status page and light control.
- Create `gateway/tests/nanomq_flow.rs`, `gateway/tests/thingsboard_flow.rs`: broker-backed integration tests, gated by test broker environment or local compose profile.
- Create `gateway/compose.yaml`, `gateway/.env.example`, update root `.gitignore`, `gateway/README.md`, and `thingsboard/README.md`: local broker, safe configuration template, run/test instructions, and manual CoreIOT setup.

Do not modify firmware files in this plan. Initial local MQTT contract: `iot/esp1/telemetry`, `iot/esp2/telemetry`, `iot/{device_id}/command`, and `iot/{device_id}/result`. Telemetry JSON is `{"ts":<epoch-ms>,"values":{...}}`; supported fields are `co2_ppm` (ESP1, finite number >= 0), `tds_ppm` (ESP2, finite number >= 0), and `light_on` (ESP2, boolean). Missing `ts` uses receive time. The firmware owners must confirm these topics/fields before device integration; if their firmware differs, update this contract, its fixtures, and implementation together. ThingsBoard names and profile names are configurable.

```rust

async fn state_and_outbox_are_written_together() {
    let store = Store::in_memory().await.unwrap();
    store.save_telemetry(sample()).await.unwrap();
    assert_eq!(store.latest("esp1").await.unwrap().unwrap().last_seen_ms, sample().timestamp_ms);
    assert_eq!(store.pending_count().await.unwrap(), 1);
}
```
- [ ] **Step 2: Run `cargo test --manifest-path gateway/Cargo.toml store::`** and confirm the tests fail.
- [ ] **Step 3: Create these tables and transaction:**

```sql
CREATE TABLE device_state (
  device_id TEXT PRIMARY KEY, thingsboard_name TEXT NOT NULL,
  payload_json TEXT NOT NULL, last_seen_ms INTEGER NOT NULL
);
CREATE TABLE telemetry_outbox (
  id INTEGER PRIMARY KEY, device_id TEXT NOT NULL, payload_json TEXT NOT NULL,
  created_at_ms INTEGER NOT NULL, attempts INTEGER NOT NULL DEFAULT 0,
  next_attempt_ms INTEGER NOT NULL, last_error TEXT
);
```

`save_telemetry` upserts `device_state` and inserts `telemetry_outbox` in one SQLx transaction. Delete an outbox row after confirmed QoS 1 PUBACK; on failure increment `attempts`, set `next_attempt_ms`, and retain the row.
